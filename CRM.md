# Подключение NOSLEEP к CRM

Сайт собирает заказ в окне оформления и отправляет его одним JSON-запросом на адрес, который вы укажете. Код сайта под конкретную CRM менять не нужно. Подключение делается через сервис-посредник или свою серверную функцию.

```
Покупатель → окно оформления → POST JSON → посредник (Albato / ApiX-Drive / Make) → ваша CRM
```

## Что понадобится

- Хостинг и домен для сайта. На ссылке claude.ai формы не могут отправлять данные наружу.
- Аккаунт в CRM: RetailCRM, МойСклад, Битрикс24, amoCRM или любая другая, с которой работает посредник.
- Аккаунт в сервисе-посреднике или своя серверная функция, например в Yandex Cloud Functions.
- Страница с политикой обработки персональных данных на вашем сайте (152-ФЗ).

## Настройка за 5 шагов

1. **Создайте приёмник заказов в посреднике.** В Albato, ApiX-Drive или Make создайте связку, которая запускается от входящего вебхука. Сервис выдаст адрес вида `https://…`.
2. **Вставьте адрес в сайт.** Откройте `index.html`, найдите в конце файла блок `CONFIG` и заполните поля:
   ```js
   webhookUrl: 'https://адрес-из-посредника',
   policyUrl: 'https://ваш-сайт.ru/privacy',
   ```
3. **Отправьте тестовый заказ,** чтобы посредник увидел структуру данных. Посредники обычно просят сделать это перед настройкой полей.
4. **Сопоставьте поля.** Укажите в посреднике, какое поле заказа куда класть в CRM. Список полей ниже, типичная схема такая:
   - `customer.*` → контакт или клиент;
   - `items[]` → товары заказа;
   - `delivery.*` → доставка;
   - `totals.total` → сумма;
   - `order_id` → внешний номер заказа.
5. **Проверьте живой заказ** с сайта на хостинге и убедитесь, что он появился в CRM.

Если посредник не принимает запросы с сайта (ошибка CORS), поставьте в `CONFIG` значение `transport: 'beacon'`. Запрос будет уходить в любом случае, но сайт перестанет видеть, дошёл ли он, и не сможет предложить повтор при сбое.

## Блок настроек CONFIG

| Поле | Что задаёт |
| --- | --- |
| `webhookUrl` | Адрес приёмника заказов. Пусто — демо-режим: заказ никуда не уходит, а покупатель видит его данные |
| `transport` | `'fetch'` (по умолчанию, видит ошибки) или `'beacon'` (для приёмников без CORS) |
| `timeoutMs` | Сколько ждать ответа приёмника, в миллисекундах |
| `policyUrl` | Ссылка на политику конфиденциальности. Появляется в согласии и в подвале |
| `freeShippingFrom` | Порог бесплатной доставки, в рублях |
| `promo` | Промокод и процент скидки |
| `delivery` | Способы доставки: название, подпись, цена и тип адреса (`pickup`, `door`, `post`) |

Для способа `post` индекс обязателен, для `door` — необязателен, для `pickup` поле индекса скрыто, а в поле адреса указывается адрес или код пункта выдачи.

## Что приходит в CRM

Пример заказа:

```json
{
  "event": "order.created",
  "order_id": "NS-260926-WYYK",
  "created_at": "2026-09-26T19:59:23.359Z",
  "shop": "NOSLEEP",
  "currency": "RUB",
  "customer": {
    "full_name": "Петров Иван Сергеевич",
    "last_name": "Петров",
    "first_name": "Иван",
    "middle_name": "Сергеевич",
    "phone": "+79161234567",
    "email": "ivan@mail.ru"
  },
  "delivery": {
    "method": "courier",
    "method_name": "Курьер до двери",
    "city": "Москва",
    "address": "ул. Тверская, 7, кв. 3",
    "postcode": null,
    "comment": "домофон 3",
    "price": 490
  },
  "items": [
    {
      "sku": "battery-s-m",
      "product_id": "battery",
      "name": "\"Low Battery\" JORTS",
      "size": "S-M",
      "qty": 1,
      "price": 4490,
      "sum": 4490
    }
  ],
  "totals": { "subtotal": 4490, "discount": 449, "delivery": 490, "total": 4531 },
  "promo_code": "NOSLEEP",
  "consent": {
    "personal_data": true,
    "policy_url": "https://nosleep.ru/privacy",
    "accepted_at": "2026-09-26T19:59:23.359Z"
  },
  "source": {
    "page": "https://nosleep.ru/",
    "referrer": "https://yandex.ru/",
    "utm": { "utm_source": "vk", "utm_campaign": "drop04" }
  }
}
```

Пояснения к полям:

- **`order_id`** создаётся один раз на заказ и не меняется при повторной отправке после сбоя. Используйте его в CRM как внешний номер, чтобы отсеивать дубли.
- **`customer.phone`** всегда в формате `+7XXXXXXXXXX`.
- **ФИО** делится на части по порядку «Фамилия Имя Отчество». Если отчества нет, `middle_name` будет `null`.
- **`items[].sku`** — это модель и размер. По нему удобно связывать товары с артикулами в CRM или на складе.
- **Суммы** указаны в рублях, целыми числами. `delivery.price` равна `0`, если сработала бесплатная доставка.
- **`source.utm`** — рекламные метки из ссылки, по которой покупатель пришёл на сайт. Сохраняются на всё время визита.

## Для аналитики

После успешного заказа сайт:

- генерирует событие `nosleep:order` на `window` с полными данными заказа в `event.detail`;
- добавляет в `window.dataLayer` запись `{event: 'order_created', order_id, value, currency}`, если на странице подключён Google Tag Manager или Яндекс Метрика через dataLayer.

## Что уже сделано на сайте

- Проверка полей: город, адрес, индекс для Почты России, ФИО из двух и более слов, телефон из 10 цифр после +7, почта в правильном формате.
- Маска телефона `+7 (XXX) XXX-XX-XX`, которая принимает номера с 8 и +7.
- Обязательная галочка согласия на обработку персональных данных.
- Скрытое поле-ловушка для ботов. Такие заявки не отправляются.
- Если отправка не удалась, корзина и введённые данные сохраняются, а покупатель может нажать «Подтвердить» ещё раз.

## Чего сайт не делает

- **Не принимает оплату.** Обычно менеджер подтверждает заказ и отправляет ссылку на оплату. Эквайринг ⟨ЮKassa, CloudPayments и другие⟩ подключается отдельно.
- **Не получает остатки из CRM.** Цены, остатки и пометки Sold out хранятся в массиве `P` в `index.html`. Чтобы они подтягивались из CRM или со склада автоматически, нужна отдельная доработка под конкретную систему.
- **Не проверяет данные на сервере.** Проверка идёт только в браузере. Если заказы принимает своя функция, а не посредник, стоит продублировать в ней проверку телефона и суммы.
